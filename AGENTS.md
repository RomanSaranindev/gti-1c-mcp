# AGENTS.md — Инструкция для ИИ-агента (AI Setup Guide)

Этот файл объясняет ИИ-модели (Claude, ChatGPT, Cursor, OpenCode и другим агентам), **что такое этот сервер**, **как его развернуть** и **как с ним работать**.

---

## Что такое gti-1c-mcp

`gti-1c-mcp` — это **MCP-сервер** (Model Context Protocol) для работы с корпоративной системой **1С:БИТ.СТРОИТЕЛЬСТВО (БИТ.ФИНАНС)**.

Он даёт ИИ-агенту доступ к:
- **75 инструкциям пользователя 1С.БИТ** — полнотекстовый и семантический поиск
- **Маршрутам согласования** по организациям — подбор цепочки, сравнение, блок-схемы
- **Живой базе 1С** — запросы к рабочей базе через HTTP-сервис расширения

Всего **18 инструментов**. Доступ — по персональному токену с ролью `user`, `analyst` или `admin`.

---

## Модель безопасности

Сервер работает с продуктивной базой, поэтому доступ ограничен на четырёх уровнях.

### 1. Персональные токены вместо общего пароля

Общего токена нет. Каждый пользователь получает свой, привязанный к его доменному логину 1С и роли. Токен хранится только в виде SHA-256 хеша — утечка `tokens.json` не даёт возможности подключиться.

Токен передаётся **только** заголовком `X-MCP-Token`. Приём через `?token=` намеренно не поддерживается: query-строка оседает в логах прокси и в заголовке `Referer`.

### 2. Делегирование identity

Запрос к 1С выполняется **под доменной учёткой владельца токена**, а не под общим техпользователем. Поэтому права базы и RLS применяются к конкретному сотруднику: пользователь видит ровно то, что ему разрешено в 1С.

Технически это `AsyncLocalStorage` — параллельные запросы разных пользователей не перемешиваются.

### 3. Роли

| Роль | Доступ | Инструментов |
|---|---|---|
| `user` | Инструкции + `check_document_access` (проверка **своих** прав на документ) | 4 |
| `analyst` | Всё, кроме `execute_1c_query`: маршруты, визы, права, документы, метаданные | 17 |
| `admin` | То же + `execute_1c_query`, `POST /reload`, `GET /status` | 18 |

Разграничение задаётся картой `TOOL_ACCESS` в `src/server.js` — единственным источником правды. Инструмент, отсутствующий в карте, недоступен никому: забыть добавить новый инструмент безопаснее, чем случайно открыть его всем.

**Инструменты не своей роли не регистрируются** и не видны в `tools/list` — агент не тратит вызовы на заведомые отказы. Проверка роли в `guard()` остаётся второй линией обороны: список инструментов — удобство, а не граница безопасности.

Почему роли разделены именно так:

- **`user`** — рядовому сотруднику нужны инструкции («как оформить документ») и ответ на вопрос «каких прав мне не хватает». Данные живой базы — чужие документы, состав групп, матрица виз — для этого не требуются.
- **`analyst`** — работает с данными через специализированные инструменты, где состав возвращаемых полей задан кодом и проверен на ПДн.
- **`admin`** — `execute_1c_query` позволяет обратиться к любой таблице базы в обход остальных инструментов, поэтому закрыт для всех остальных.

### 4. Защита персональных данных — в BSL

ФИО, логины и контактные данные не покидают 1С. Проверка сделана **внутри расширения** (`ПроверитьЗапросНаПерсональныеДанные`), а не на стороне Node: это единственная реальная граница доверия — проверку «снаружи» можно обойти, подключившись к 1С напрямую.

Заблокировано:
- **таблицы целиком** — `Справочник.ФизическиеЛица`, `Справочник.Сотрудники`, `Справочник.КонтактныеЛица`, регистры контактной информации и паспортных данных;
- **реквизиты `Справочник.Пользователи`** — `Наименование`, `ФИО`, `Физлицо`, `Телефон`, `Email`, `ИНН`, `СНИЛС` и другие.

Разрешены служебные поля: `Ссылка`, `ИдентификаторПользователяИБ`, `Недействителен`, `ПометкаУдаления`.

Идентификация сотрудников — только по `user_uid` = `ИдентификаторПользователяИБ`.

### 5. Аудит

Каждый вызов пишется в stderr одной JSON-строкой с префиксом `AUDIT`:

```json
AUDIT {"ts":"...","actor":"HG\\ИвановИИ","token_id":"tok_a1b2","role":"admin",
       "action":"execute_1c_query","result":"ok","ms":183,
       "args":{"query":"ВЫБРАТЬ ...","limit":100}}
```

Для `execute_1c_query` текст запроса пишется целиком. Отказы (`result: "denied"`) фиксируются тоже.

### 6. TLS

Соединение с 1С проверяется строго. Доверие к внутреннему УЦ задаётся бандлом `cert/hg-ca-bundle.pem` (HG Root CA + HG Issuing CA), который читается в коде. Отключение проверки сертификата недопустимо: по этому каналу передаётся пароль 1С.

## Выдача токенов

### Первичная настройка

```bash
# 1. Сгенерировать ключ шифрования (один раз на сервер)
node tools/token.mjs genkey
# → добавить MCP_SECRET_KEY=... в .env
```

### Выдать токен пользователю

```bash
# Обычный пользователь: инструкции + проверка своих прав
node --env-file=.env tools/token.mjs issue \
  --login "HG\ИвановИИ" --comment "Иванов, бухгалтерия"

# Аналитик: всё, кроме произвольного запроса
node --env-file=.env tools/token.mjs issue \
  --login "HG\СидороваАА" --role analyst --comment "Сидорова, фин.контроль"

# Администратор, на 90 дней
node --env-file=.env tools/token.mjs issue \
  --login "HG\ПетровПП" --role admin --days 90 --comment "Петров, ИТ"
```

Роль по умолчанию — `user`. Выдавайте `analyst` только тем, кому нужны данные живой базы, а `admin` — тем, кому действительно нужен произвольный запрос.

Пароль запрашивается интерактивно (скрытый ввод) или передаётся через `--password`.

Команда печатает токен **один раз** — повторно показать его нельзя, хранится только хеш. Вместе с токеном выводится готовый конфиг для MCP-клиента.

### Ведение реестра

```bash
node --env-file=.env tools/token.mjs list                    # все токены и их состояние
node --env-file=.env tools/token.mjs revoke  --id tok_a1b2c3 # отозвать (при увольнении)
node --env-file=.env tools/token.mjs restore --id tok_a1b2c3 # вернуть доступ
node --env-file=.env tools/token.mjs remove  --id tok_a1b2c3 # удалить запись
```

`list` показывает дату последнего использования — по ней видно неактивные учётки. Отзыв действует немедленно: реестр читается на каждом запросе.

**Правила ведения:**
- срок по умолчанию — 365 дней, для admin рекомендуется меньше;
- `--comment` обязателен по смыслу: без него через полгода непонятно, чей это токен;
- при увольнении — `revoke`, не `remove` (запись нужна для разбора журнала);
- `tokens.json` в `.gitignore`, права `0600`, в бэкапы попадать не должен;
- смена `MCP_SECRET_KEY` инвалидирует все токены — потребуется перевыпуск.

## Быстрый старт

```bash
git clone https://gitlab.ide-spb.com/saraninrg/gti-1c-mcp.git
cd gti-1c-mcp
npm install

cp .env.example .env        # Windows: copy .env.example .env
node tools/token.mjs genkey # → MCP_SECRET_KEY в .env
# заполнить ONEC_URL, ONEC_USERNAME, ONEC_PASSWORD

node --env-file=.env tools/token.mjs issue --login "HG\ВашЛогин" --role admin
npm start
```

Проверка: `curl http://localhost:3031/health`

### Режимы запуска

```bash
npm start          # HTTP на порту 3031 (по умолчанию)
npm run stdio      # stdio — для локальных MCP-клиентов
```

Режим задаётся явно флагом `--stdio` или `MCP_TRANSPORT=stdio`. По TTY он **не** определяется: при запуске службой или через `Start-Process` stdin не является терминалом, и прежняя эвристика молча уводила сервер в stdio, не открывая порт.

### Подключение клиента

```json
{
  "mcp": {
    "gti-1c": {
      "type": "remote",
      "url": "http://localhost:3031/mcp",
      "headers": { "X-MCP-Token": "gti_ваш_токен" },
      "enabled": true
    }
  }
}
```

## Расширение 1С

Основано на [vladimir-kharin/1c_mcp](https://github.com/vladimir-kharin/1c_mcp).

```
ИИ-агент → MCP → gti-1c-mcp (:3031) → JSON-RPC/HTTPS/Basic → 1С (/hs/mcp/rpc)
```

**Установка:** Конфигуратор → Расширения конфигурации → добавить `build/MCP_Сервер.cfe` → опубликовать базу через Apache/IIS.

> Регистр имени базы в URL должен совпадать с именем публикации (`base`, не `Base`), иначе 1С перенаправляет POST→GET.

**Пересборка после правки BSL:**

```bash
python -m v8unpack -B cfe_src build/MCP_Сервер.cfe
```

Затем: Конфигуратор → Расширения → MCP_Сервер → **Обновить из файла** и перезапустить сеансы. Без этого шага изменения BSL (в том числе блокировка ПДн) не действуют.

## Инструменты (18)

### База знаний инструкций (75 документов) — роль `user`

| Инструмент | Назначение |
|---|---|
| `list_instructions` | Список инструкций. Параметры: `filter_code`, `filter_keyword`, `topic`, `list_topics` |
| `search_instructions` | Поиск. `mode`: `auto`/`semantic` (TF-IDF) или `keyword` (точное совпадение) |
| `get_instruction` | Полный текст по `id` или коду `ИП-301` |

### Самодиагностика прав — роль `user`

| Инструмент | Назначение |
|---|---|
| `check_document_access` | Каких прав не хватает для работы с документом + какие профили их дают |

Отвечает на вопрос «почему я не могу провести документ». Проверяет права `Чтение`, `Добавление`, `Изменение`, `Проведение`, `ПометкаУдаления` на тип документа и по каждому возвращает признак наличия. Для недостающих подбирает профили групп доступа, отсортированные по покрытию — такой профиль сотрудник и запрашивает у администратора.

Роль `user` всегда получает ответ **только про себя**: параметр `user_uid` для неё отклоняется, а без него расширение проверяет текущего пользователя сеанса 1С, то есть владельца токена. Диагностика чужих прав доступна ролям `analyst` и `admin`.

Проверка идёт по правам на объект метаданных. Ограничения на уровне записей (RLS) — организация, ЦФО, склад — этой проверкой не оцениваются, о чём сказано в поле `note` ответа.

### Маршруты согласования — роль `analyst`

| Инструмент | Назначение |
|---|---|
| `list_routes` | Список маршрутов по организациям |
| `suggest_route` | Подбор цепочки: `org`, `doc_type`, `amount`, `cfo`, `project` и др. |
| `get_route` | Полный маршрут организации без фильтрации |
| `compare_routes` | Сравнение маршрутов двух организаций |
| `validate_route_params` | Проверка параметров перед `suggest_route` |

Коды документов: `ЦС-001` Конкурентная карта, `ЦС-002` Заявка на МПЗ, `ЦС-003` Заявка на затраты, `ЦС-004` Заявка на расход ДС, `ЦС-005` Реестр платежей, `ЦС-006` Корректировка контрольных значений, `Заказ поставщику`.

Данные в `knowledge/routes/routes_db.json` обезличены: вместо ФИО — роли и визы. Роли с постфиксом **БЕ** привязаны к бизнес-единице.

### Живая база 1С — роль `analyst`

| Инструмент | Назначение |
|---|---|
| `onec_health` | **Вызывать первым.** Проверка подключения и списка инструментов расширения |
| `list_1c_users` | Пользователи **без ФИО**: `user_uid`, подразделение, признаки активности |
| `get_1c_access_groups` | Группы доступа: наименование, профиль, число участников |
| `get_1c_metadata` | Метаданные конфигурации. Запросы по типам идут параллельно |
| `get_1c_documents` | Документы БИТ.ФИНАНС с полями шапки |
| `get_visa_routes` | Визы, маршруты, права установки виз, шаги алгоритма, блок-схема (Mermaid) |
| `get_user_rights` | Группы и профили по `user_ref` |
| `get_user_visas` | Визы согласования по `user_uid` |
| `execute_1c_query` | **Только `admin`.** Произвольный запрос на чтение |

#### Отбор прав установки виз по сотруднику

`get_visa_routes(mode="rights")` принимает `user_uid` и отвечает на вопрос «какие визы может ставить этот сотрудник»:

```
get_visa_routes(mode="rights", user_uid="490933bc-311e-41d5-bcc4-eeb4b996ebf5")
```

Измерение `Пользователь` регистра `бит_ПраваУстановкиВиз` — составного типа: право выдаётся либо персонально, либо группе пользователей. На практике почти всегда группе, поэтому по умолчанию (`include_groups=true`) учитываются оба варианта, а каждая строка ответа помечена `granted_via`: `direct` или `group`. С `include_groups=false` остаются только персональные права — как правило, пустой результат.

## Типичные сценарии

**Найти инструкцию**
```
search_instructions(query="создать путевой лист") → ИП-301
get_instruction(id="ИП-301")
```

**Маршрут согласования**
```
suggest_route(org="ГТИ", doc_type="ЦС-004", amount=6000000)
→ Инициатор → Финансовый контроль БЕ [ГТИ] → Генеральный директор БЕ [ГТИ]
```

**Права пользователя (без ФИО)**
```
list_1c_users(department="Бухгалтерия")     → user_uid
get_user_rights(user_ref="Справочник.Пользователи?ref=<hex>")
```

**Произвольный запрос (admin)**
```
get_1c_metadata(object_type="catalogs", object_name="Контрагент", include_attributes=true)
execute_1c_query(
  query_text="ВЫБРАТЬ Наименование, ИНН ИЗ Справочник.Контрагенты ГДЕ Город = &Город",
  params={"Город": "Чита"}, limit=50)
```

## Эндпоинты

| Эндпоинт | Метод | Доступ | Назначение |
|---|---|---|---|
| `/health` | GET | без токена | Признак живости (только статус и версия) |
| `/` | GET | без токена | Краткая справка по подключению |
| `/mcp` | POST | токен | MCP-протокол |
| `/status` | GET | `admin` | Подробное состояние: сессии, индекс, подключение к 1С |
| `/reload` | POST | `admin` | Горячая перезагрузка базы знаний |

`/health` намеренно скупой: состав инструментов и статус подключения к 1С раньше отдавались анониму и служили разведданными. Подробности — в `/status`.

| `MCP_SESSION_SWEEP` | `300000` | Период чистки сессий, мс |
| `MCP_MAX_SESSIONS` | `100` | Лимит сессий; при переполнении вытесняется старейшая |

## Проверка после изменений

```bash
node tools/check_all.mjs <user-токен> <analyst-токен> <admin-токен>
```

Проверяет разграничение по трём ролям, блокировку ПДн, read-only, отбор прав виз по сотруднику, самодиагностику прав на документ и работоспособность инструментов.

## Типичные ошибки

| Симптом | Причина | Решение |
|---|---|---|
| `401 Unauthorized` | Нет заголовка, токен неизвестен, отозван или истёк | `tools/token.mjs list` — проверить состояние |
| `403 Forbidden` | Инструмент требует роль `admin` | Выдать admin-токен либо использовать специализированный инструмент |
| `unable to get local issuer certificate` | Нет `cert/hg-ca-bundle.pem` | Восстановить бандл или указать `ONEC_CA_BUNDLE` |
| Ошибка 1С `401` | Неверный доменный логин/пароль в токене | Перевыпустить токен с корректными данными |
| ПДн-запрос проходит | Расширение не обновлено в базе | Пересобрать `.cfe` и «Обновить из файла», перезапустить сеансы |
| Порт не слушается | Запущен stdio-режим | Убрать `--stdio` / `MCP_TRANSPORT=stdio` |
| `MCP_SECRET_KEY не задан` | Нет ключа в `.env` | `node tools/token.mjs genkey` |
| Инструкция не находится | Файл добавлен после старта | `POST /reload` (admin) или подождать `fs.watch` |
