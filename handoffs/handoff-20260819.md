## Ключевые дефекты, найденные и устранённые

1. **`Запрос.Текст` не присваивался** в `ВизыНаДокументах` и `МаршрутыАлгоритмов` → `Ожидается выражение ВЫБРАТЬ`.
2. **`МаршрутыАлгоритмов`** соединял ТЧ `ПараметрыАлгоритма` (метаданные алгоритма), а не шаги маршрута из `бит_УстановленныеВизы`.
3. **Псевдоним `КАК Значение`** — зарезервированное слово, роняло компиляцию всего модуля (HTTP 500 на всех инструментах).
4. **`КодАлгоритма` не объявлен** в параметрах `МаршрутыАлгоритмов` — выявлено только через `/CheckConfig`, не через `/CheckModules`.
5. **Пороги сумм** лежат в `ПользовательскиеУсловия.ПроизвольноеУсловие` (BSL-выражение), а не в ТЧ `Условия` (та пустая). Fallback на `ПроизвольноеУсловие` сработал — пороги пришли.
6. **Ветки «Нет» у условий** — связь пишется только с одной стороны (источник ИЛИ приёмник). Исправлено: берём `ИсходящиеТочки ОБЪЕДИНИТЬ ВСЕ ВходящиеТочки`, снятие дублей в коде по паре «от→к».
7. **Визы шагов**: было 8/17 действий с визами (только история). Исправлено: из `ПользовательскоеДействие.Виза` — 17/17.
8. **Литерный фильтр «ОД»** давал «РукОВОДитель» через подстроку. Исправлено: поиск по наименованию включается только для длинного ввода.
9. **`МАКСИМУМ(ЗначениеУсловия)`** по составному типу (3 547 типов) → ошибка компиляции запроса в рантайме. Снятие дублей переведено в код.

## Кандидаты для долгосрочной памяти

Если у проекта есть `memory.md` или `1c-templates-mcp recall` — стоит зафиксировать:

- **`/CheckModules` не ловит ошибки в тексте запросов и необъявленные переменные в 1С.** Полноценная проверка только через `/CheckConfig -IncorrectReferences`. Это критично при работе с расширениями — их легко загрузить, не заметив ошибку компиляции BSL.
- **`МАКСИМУМ`/`РАЗЛИЧНЫЕ` по составному типу в 1С** (тип с >1 допустимым значением) неприменимы в запросе — ошибка в рантайме, не в синтаксисе.
- **`Значение`, `Ссылка`, `Дата`, `Тип`** — зарезервированные псевдонимы в языке запросов 1С, псевдонимом быть не могут (используй `ЗначениеУсловияПравила`, `СсылкаОбъекта` и т.п.).
- **`РС.бит_УстановленныеВизы`**: реквизит `Маршрут` в базе ГТИ не заполняется; для группировки маршрутов использовать `Алгоритм.Код + Алгоритм.Наименование`.
- **`бит_ТочкиАлгоритмов.ИсходящиеТочки / ВходящиеТочки`**: связь пишется только с одной стороны, нужно объединение обеих ТЧ.
- **`бит_ПользовательскиеУсловия.ПроизвольноеУсловие`**: реальные пороги сумм (BSL-выражение); ТЧ `Условия` в базе ГТИ пустая.
- **`бит_ПользовательскиеДействия.Виза`**: источник назначенной визы шага в настройках маршрута (в отличие от истории через `бит_УстановленныеВизы`).
